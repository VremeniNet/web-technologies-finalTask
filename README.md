## Описание проекта

Проект представляет собой веб-приложение для управления списком задач. Серверная часть реализована на Node.js с использованием Express, а пользовательский интерфейс создан на HTML, CSS и JavaScript без дополнительных фронтенд-фреймворков.

Приложение позволяет создавать задачи, получать их список, редактировать названия, отмечать задачи выполненными и удалять записи. Все изменения сохраняются в облачной базе MongoDB Atlas, поэтому данные остаются доступными после перезапуска приложения.

Доступ к API защищён Bearer-токеном. Пользователь вводит токен в интерфейсе самостоятельно; в исходном коде браузера он не хранится.

## Локальный запуск

Для запуска потребуется совместимая версия Node.js и доступ к MongoDB Atlas.

1. Клонировать репозиторий.
2. Установить зависимости.
3. Скопировать `.env.example` в `.env` и заполнить параметры.
4. Убедиться, что текущий IP разрешён в MongoDB Atlas.
5. Запустить сервер.

```powershell
git clone https://github.com/VremeniNet/web-technologies-finalTask.git
cd web-technologies-finalTask
npm ci
Copy-Item .env.example .env
npm start
```

После запуска приложение доступно по адресу `http://127.0.0.1:3000/`.

Основные переменные окружения: `PORT`, `MOODLE_LOGIN`, `FULL_NAME`, `API_TOKEN`, `DB_NAME`, `MONGODB_URI`. Настоящие значения паролей и токенов не публикуются.

## HTTP API

| Метод | Маршрут | Назначение |
|---|---|---|
| GET | `/login/` | Логин Moodle, публичный маршрут |
| GET | `/api/author/` | Сведения об авторе |
| POST | `/api/tasks/` | Создание задачи |
| GET | `/api/tasks/?runId=manual` | Получение списка |
| GET | `/api/tasks/:id/` | Получение одной задачи |
| PATCH | `/api/tasks/:id/` | Изменение задачи |
| DELETE | `/api/tasks/:id/` | Удаление задачи |

Все маршруты `/api/` требуют заголовок `Authorization: Bearer TOKEN`. Ошибочные запросы получают соответствующие HTTP-статусы и JSON с полем `error`.

## Структура базы данных

Используется база `todo_vremeninet` и коллекция `tasks`. Каждый документ содержит уникальный строковый UUID `id`, логин владельца `ownerLogin`, название `title`, булево значение `done`, идентификатор запуска `runId` и дату создания `createdAt` в UTC.

Сервер самостоятельно формирует идентификатор, владельца, дату создания и начальный статус задачи. На поле `id` создаётся уникальный индекс. Обязательная запись с названием `Итоговая работа 24.10.2026: vremeninet` хранится с `runId = manual`.

## Доступ преподавателя и безопасность

Для приложения используется пользователь MongoDB `todo_app`. Для независимой проверки предусмотрен отдельный пользователь `todo_reviewer` с ролью `todo_rw`, ограниченной учебной базой. Преподаватель может проверять чтение, вставку, изменение и удаление документов без обращения к HTTP API.

Учётные данные преподавателю передаются отдельно через личное сообщение Moodle. Файлы `.env` и `node_modules` исключены из Git, а в репозитории размещён только `.env.example` без секретов.
